\section{Data Representation and Preprocessing}\label{sec:method:data}

All training and evaluation data are synthetic because operational \gls{elint} recordings are scarce and sensitive.
A scenario simulator generates time-ordered \gls{pdw} recordings with varying numbers of emitters and operating modes \parencite{jonsson2023supcon}.
Each pulse contains the measured parameters and per-pulse labels defined in \cref{sec:method:formulation}.
The composition of the resulting corpus is reported in \cref{sec:exp:datasets}.

Preprocessing first scales the measured pulse parameters using statistics from the training split.
Optional timing features are then computed as described in \cref{sec:method:features}, after which each pulse train is divided into fixed-length windows.

\subsection{Per-feature scaling}\label{sec:method:data:norm}

Let $\mathcal{P}_{\mathrm{tr}}$ denote the multiset of all pulses in the training split, pooled across pulse trains.
All scaling statistics are estimated on $\mathcal{P}_{\mathrm{tr}}$ and applied unchanged to validation and test data.
Pooling across pulse trains preserves the absolute parameter ranges used to compare operating modes globally; fitting each train separately would remove this information.

For each parameter $g \in \{f,\,\mathrm{PW},\,\log_{10} A\}$, the training-set mean and variance are
\begin{equation}\label{eq:method:standardize_stats}
  \mu_g = \frac{1}{\lvert\mathcal{P}_{\mathrm{tr}}\rvert}
  \sum_{n \in \mathcal{P}_{\mathrm{tr}}} g_n,
  \qquad
  \sigma_g^2 = \frac{1}{\lvert\mathcal{P}_{\mathrm{tr}}\rvert}
  \sum_{n \in \mathcal{P}_{\mathrm{tr}}} (g_n - \mu_g)^2,
\end{equation}
and the standardized value is
\begin{equation}\label{eq:method:standardize}
  \tilde{g}_n = \frac{g_n - \mu_g}{\sigma_g}.
\end{equation}
Amplitude is transformed as $\log_{10} A_n$ before standardization to reduce its dynamic range.

Time of arrival $t_n$ is min--max scaled using the training-corpus extrema,
\begin{equation}\label{eq:method:minmax}
  \tilde{t}_n
  =
  \frac{t_n - t_{\min}}{t_{\max} - t_{\min}},
\end{equation}
whereas the two \gls{aoa} components are mapped from their physical intervals to $[0,1]$:
\begin{equation}\label{eq:method:aoa_rescale}
  \tilde{\theta}^{\mathrm{az}}_n = \frac{\theta^{\mathrm{az}}_n}{2\pi},
  \qquad
  \tilde{\theta}^{\mathrm{lat}}_n = \frac{\theta^{\mathrm{lat}}_n}{\pi}.
\end{equation}
Here $\theta^{\mathrm{az}}_n \in [0,2\pi]$ and $\theta^{\mathrm{lat}}_n \in [0,\pi]$.

\subsection{Windowing}\label{sec:method:data:window}

Standard self-attention has time and memory complexity $\mathcal{O}(L^2)$ for a window of $L$ pulses.
Because a complete pulse train may contain millions of pulses, the encoder processes fixed-length windows rather than entire trains.
The value of $L$ is reported with the experimental hyperparameters in \cref{tab:exp:hparams_main}.

Given a pulse train $\mat{X}=(\vect{x}_1,\ldots,\vect{x}_N)$ and stride $s$, window $w$ is
\begin{equation}\label{eq:method:windowing}
  \mat{X}^{(w)}
  =
  \bigl(\vect{x}_{1+(w-1)s},\ldots,\vect{x}_{L+(w-1)s}\bigr),
  \qquad
  w \in
  \left\{1,\ldots,\left\lfloor\frac{N-L}{s}\right\rfloor+1\right\}.
\end{equation}
The number of windows therefore varies with the pulse-train length.
Any trailing segment shorter than $L$ is dropped.

Training uses $s=L/2$, so adjacent windows overlap by half their length.
This exposes pulse patterns at different window offsets and reduces sensitivity to boundaries that coincide with mode transitions.
The scenario-aware sampler in \cref{sec:method:training:sampler} places related windows in the same mini-batch so that the contrastive loss can use these repeated views.
Validation and test use $s=L$ to avoid evaluating overlapping copies of the same pulses.

Each window retains the emitter label, mode label, and pulse-train identifier associated with every pulse.
The emitter and mode labels supervise their respective branches and provide evaluation targets.
The pulse-train identifier is not an encoder input or prediction target; it is used to keep train-local emitter identifiers distinct and to form scenario-aware mini-batches.
